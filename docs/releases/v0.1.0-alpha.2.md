# MachineryPro AI v0.1.0-alpha.2 — Empirical Engineering Data Foundation

This is the second public alpha engineering release of **MachineryPro AI**.

The release extends the deterministic machining foundation established in
`v0.1.0-alpha.1` and introduces the governed empirical engineering data layer
required for future parameter recommendation, machine validation, DFM, CAPP,
and CAM intelligence.

## Included in this release

### Stage 3C — Deterministic Milling Core

- deterministic milling calculations
- milling-specific engineering rules
- explicit unit and validation behavior
- deterministic milling test coverage

### Stage 3D — Deterministic Drilling Core

- drilling geometry and feed relationships
- effective travel and machining-time calculations
- drilling MRR and validation rules
- deterministic drilling test coverage

### Stage 3E — Deterministic Threading Core

- pitch / lead relationships
- synchronized threading and tapping feed
- threading machining time and revolution calculations
- deterministic thread rule validation

### Stage 3F — Deterministic Hole Finishing Core

- reaming / boring stock relationships
- diametral and radial stock
- annular volume and MRR
- effective travel and machining-time calculations

### Stage 3G — Empirical Engineering Data Foundation

The largest architectural addition in this release is the governed empirical
engineering data foundation.

It introduces:

- typed empirical cutting-parameter records
- explicit parameter identity
- unit-safe parameter ranges
- process applicability
- material applicability
- tool applicability
- provenance-mandatory authority rules
- engineering evidence classification
- deterministic registry / lookup behavior
- duplicate handling
- conflict preservation
- fail-closed authority validation

## Engineering Authority Model

MachineryPro AI continues to follow the principle:

> Deterministic engineering calculations are authoritative.
> Empirical engineering data may act as authoritative input only when its
> provenance and applicability are explicitly validated.
> AI remains advisory and must not silently override validated engineering data.

## Provenance and Fail-Closed Behavior

Stage 3G establishes a strict rule:

**Unsourced engineering data is not authoritative.**

Records intended for engineering authority must retain:

- record identity
- parameter identity
- unit-explicit value or range
- process applicability
- material / tool applicability where defined
- provenance
- source reference
- evidence classification

Multiple matching or conflicting records are preserved rather than silently
averaged or ranked.

## CAM Source Material Policy

The local CAM research material was used only as reference material during
architecture discovery.

Approximate tutorial values are **not production seed data** and are not
treated as validated machining recommendations.

No production feeds-and-speeds database is included in this release.

## Validation

The release baseline has passed:

- Stage 3G targeted tests
- existing machining regression tests
- full test suite excluding the known source-material smoke/environment test
- targeted Ruff validation
- git diff integrity checks

Historical repository-wide Ruff debt remains outside the Stage 3G scope and
was not modified as part of this release.

## Release Status

**Alpha — Empirical Engineering Data Foundation**

This remains an engineering alpha release.

It is not yet a production-ready CAM, CAPP, DFM, quoting, or autonomous
machining platform.

## Not Included Yet

This release does not yet provide:

- automatic feeds-and-speeds recommendations
- machine capability validation
- tool selection
- machine selection
- CAD manufacturing feature recognition
- DFM automation
- CAPP
- CAM toolpath generation
- CNC connectivity
- costing / quotation
- AI authority
- optimization or closed-loop adaptation

## Next Direction

The recommended next engineering milestone is:

**Stage 3H — Machine Capability Validation Foundation**

This will allow deterministic machining parameters and governed empirical data
to be checked against explicit machine limits before future recommendation
logic is introduced.
